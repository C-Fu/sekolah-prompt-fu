## Background

Phase 1 purged all non-kids code so `src/app` now holds only the kids tree (`kids/page.tsx`,
`kids/map/page.tsx`, `kids/level/[slug]/page.tsx`, `kids/layout.tsx`) plus shared shell files
(`layout.tsx`, `error.tsx`, `global-error.tsx`, `not-found.tsx`, `globals.css`, the two image
routes). The i18n request config is already deterministic (bundled default-locale messages, no
request-time locale read); the level page already ships `generateStaticParams` for all 19 slugs;
there is no `next/image` usage and no `headers()`/`cookies()` call in any route — so the app is
already close to static-export ready.

Two things block a standalone GitHub Pages static deploy today:
1. The game lives under `/kids…` and the root `/` has no page. Phase 2 must make the game the root.
2. `background-music.tsx` streams from a remote `raw.githubusercontent.com` URL instead of the
   bundled `public/kids-music.mp3`, which a standalone/offline static deployment cannot rely on.

`output: 'export'` disables Next redirects/rewrites, so the root must be a real page, not a
redirect. Promotion is therefore done by relocating the kids routes to root and rewriting internal
`/kids…` links to root-relative paths.

## Artifacts this phase produces

Root kids routes, a static-export `next.config.ts`, a GitHub Pages deploy workflow, and a bundled
audio path. No new game symbols.
